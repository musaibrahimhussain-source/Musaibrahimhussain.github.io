# Mediroutine AI — Mobile App & Store Publishing Guide

Mediroutine AI is a full-stack web app (Express + SQLite + vanilla JS). This
guide explains how to wrap it as a **Capacitor** mobile app and submit it to
the Apple App Store and Google Play.

> **Important reality check before you start:** submitting to a real app store
> requires **paid developer accounts, code signing, and store review** that
> only you can complete. This guide gives you every step; it cannot click the
> submit button for you, and this sandbox cannot reach the stores.

---

## 1. What "app store ready" actually requires (do this yourself)

| Requirement | Apple App Store | Google Play |
|---|---|---|
| Developer account | Apple Developer, **$99/year** | Play Console, **$25 one-time** |
| App icon & splash | 1024×1024 icon, dark/light splash | 512×512 icon, feature graphic |
| Privacy policy URL | Required | Required (health data → high scrutiny) |
| Review | ~24h–7 days | Usually same-day |
| Health info sensitivity | High — expect questions about your data handling | High |

Because this app handles **health/medication data**, both stores will ask you
to justify data collection, storage, encryption, and sharing. Have answers
ready before submitting.

---

## 2. Prepare a deployed backend (required for a real mobile app)

A mobile app is **not** served from your developer machine. The Capacitor
webview loads the frontend, and the frontend calls your backend for data.

1. Deploy the Express backend + SQLite to a host with a public HTTPS URL
   (Railway, Render, Fly.io, a VPS, etc.).
2. In `public/index.html`, set the backend URL before `app.js` loads:

   ```html
   <script>window.MEDIROUTINE_API_URL = "https://api.yourdomain.com";</script>
   ```

   If this is unset, the frontend calls the same origin it's served from
   (current behavior — fine for the web preview).

> This is a live **production** deployment, which is separate from this
> sandbox. The base44 preview is a dev environment, not a publication target.

## 3. Build the app locally (Capacitor)

Capacitor is already wired with the scripts and `capacitor.config.json`.

```bash
npm install                # install includes @capacitor/* devDeps
npm run mobile:add-android # or: npm run mobile:add-ios
npm run mobile:sync        # copies public/ into the native project
```

Then open in the native IDE:

```bash
npm run mobile:open-android  # Android Studio
npm run mobile:open-ios      # Xcode (macOS only)
```

Notes:
- `android`/`ios` folders are generated by Capacitor and are **gitignored**
  by default — you generate them locally, you don't commit them.
- Use Android Studio / Xcode to set the app icon, splash screen, version,
  and signing, and to build the release binary (APK/AAB for Android, IPA for
  iOS).

---

## 4. Publish to the stores

**Google Play**
1. Enroll in Play Console (`$25`).
2. Build a **signed** Android App Bundle (AAB) in Android Studio.
3. Upload to Play Console → internal testing → closed/alpha → production.
4. Complete the Data safety form (health data is sensitive — be accurate).

**Apple App Store**
1. Enroll in the Apple Developer Program (`$99/year`).
2. In Xcode: set the bundle id (`com.mediroutine.ai`), code signing (needs a
   paid account's signing cert), and archive.
3. Upload via Xcode Organizer / Transporter.
4. Complete App Store Connect → App Privacy (nutrition labels) and review.

## 5. Features that are blocked right now (billing, not code)

The **AI assistant, push/email reminders and notification features are not
functional while the workspace's Integration credits are exhausted** (they
reset 2026-10-01 or you can upgrade the Base44 workspace tier). These are
not implemented bugs — the endpoints return a clear 503 explaining the
credit limit. Relying on them for a store submission today would produce an
app whose headline features don't work, so do **not** market them as live
until credits are available and the features are actually wired to a real
LLM / push / email provider.
